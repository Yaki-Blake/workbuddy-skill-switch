## 一、这能省多少

这个数得先算清楚，不然容易对它抱错期待。

WorkBuddy 会把已启用的技能拼成 `name: description` 塞进系统提示。一个技能大概是 125 token 的量级，装得越多越是线性叠加。

所以常驻开销约等于注入的技能数乘以 125，再除以每次请求的平均输入，就是它占的比例。

刚才在这台机器上跑了一遍。

| 项目        | 数值                                              |
| --------- | ----------------------------------------------- |
| 技能总数      | 149（20 个自带 `disable-model-invocation`，本来就不进上下文） |
| 实际注入的常驻开销 | ~16,082 token                                   |
| 每次请求的平均输入 | ~1,173,000 token（7.37 亿除以 628 次）                |
| 缓存命中率     | 97.4%                                           |
| 占比        | 1.37%                                           |

那个 125 是这么来的，16082 摊到 129 个真进了上下文的技能上，算出来 124.6。技能描述有长有短，单个技能的实测值在 80 到 250 之间浮动，所以这个系数只能用来估量级。

1.37%。就算把技能关掉一半，这个数也就变成 0.68%。看到这个量级之后，我就不再指望靠它省钱了。

那还剩什么用。

最直接的一点是模型挑错工具的次数少了。系统提示里平铺一百多个技能的时候，它偶尔会去调一个八竿子打不着的，清单短下来之后这种情况明显少了。这一条只能靠体感，我给不出精确数字。

另一点更实在，我能查了。每个技能占多少 token，谁在什么时候把它改成了什么状态，翻一下就有。以前改完转头就忘，现在至少有个地方记着。

真想搞明白钱花在哪，去看界面里的真实用量页，按会话排。最贵的那几次对话通常是某一轮反复重发了大文件，那种才是大头。

## 二、把它用起来

双击 `启动界面.bat`，浏览器会自己打开 `http://127.0.0.1:8899`。左边一栏是名单，右边是技能列表，上面那条搜索框按斜杠就能聚焦。右边还有推荐勾选和排序的按钮，最底下是已选数量和保存的地方。

### 第一步，把不用的挑出来

右边每个技能一行，前面有个勾选框。最省事的办法是点上面的推荐勾选，它按名字前缀分好了组，`ardot-` 开头的一族、`workbuddy-` 开头的一族，一次能勾一大片。想挑细一点就搜，或者直接点行。

勾的时候盯着最底下那行字，它会跟着变，比如「已选 12 个 · ~1.9k tok」。这个数是你选的这堆技能现在占的上下文，也是关掉之后能省下来的量。

挑完在下面输入框里起个名字，比如「不常用」，点保存名单。左边多出一张卡片，上面写着这份名单有几个成员、现在都是什么状态。

建名单这一步不写任何配置，随时能做，WorkBuddy 开着也没关系。

### 第二步，把 WorkBuddy 退干净

从托盘图标退出。点窗口右上角那个叉不算，应用还活着的时候，配置在它内存里有一份，退出那一刻会把手里的旧值刷回磁盘，把外面的修改盖掉。

### 第三步，在卡片上点关闭

点下去才会写 `settings.json`。

界面上这个「关闭」其实是休眠。模型不再自动想起这个技能，上下文也就省下来了，但你随时还能用斜杠加名字把它叫出来。我平时只用这个，真要从能力上禁掉才去用命令行的 `--hard`。

三个状态对应成这样。

| 你做的           | 状态 | 模型能自动调 | 你还能手动调 |
| ------------- | -- | ------ | ------ |
| 点开启           | 默认 | 是      | 是      |
| 点关闭           | 休眠 | 否      | 是      |
| 命令行加 `--hard` | 关闭 | 否      | 否      |

点完之后卡片上的状态分布会变，操作记录里也会多一条。

### 第四步，重启 WorkBuddy

配置是启动的时候读进内存的，不重启不生效。这个绕不过去，是时机决定的。

### 第五步，看看效果

回到界面，卡片上会显示各状态的成员数。想撤销就点同一张卡片上的开启，再重启一次。

之后日常只用两步，打开界面看一眼，需要的时候点开启或者关闭。名单建好一次就不用再动。

## 三、几个具体的东西

### 界面上那些数字

列表右边那个 `~470` 是这个技能在系统提示里占的估算值，只算名字和描述。前面的波浪号表示这是估的，红色表示超过 250 token。

有些行显示一条横线。那是技能自己声明了 `disable-model-invocation`，本来就不进上下文，关它没有任何效果。这一列能帮你少做无用功。

鼠标在任意一行上停半秒会弹出正文，`SKILL.md`，没有的话退到 `README.md`，底下标着行数和正文的 token。这个数和列表里那个是两笔账。列表里是养着它要花的钱，弹出来的这个是调用它才花的钱。

底部那行「显示 128 / 共 128 个 · 实际注入 ~16,082 tok」，前面两个是筛选后的数量和可选总数，默认只列用户级技能，打开显示全部才会带上内置和插件。后面的合计始终是真进了系统提示的那部分，所以比 `cost` 命令默认统计的范围大。

真实用量页在顶部，总积分、输入输出 token、缓存命中率都在上面。下面是两张表，用最近调用和按技能归集两个按钮切，默认是最近调用。

按技能归集只认显式的 `/技能名` 调用，覆盖率很低，原因写在第五节。总积分和按会话的统计是准的。另外一轮对话里如果调了多个技能，那一轮的成本会在每个技能名下各记一遍，所以这张表加起来会比右上角的技能轮次积分大，不是我算错了。

### 命令行

平时用界面就够了，这一节留给写脚本和自己排查的时候。

```bash
python skillset.py ls                  # 全部名单与状态分布
python skillset.py cost --top 20       # 按开销排序，先关谁
python skillset.py off 编程 --dry-run   # 演练，不写文件
python skillset.py off 编程             # 休眠整份名单
python skillset.py off 编程 --hard      # 彻底关闭
python skillset.py on 编程              # 恢复
python skillset.py status              # 谁被改过、谁改的
python skillset.py restore             # 从最近一次备份恢复
```

全部十三个子命令。

| 命令                                 | 作用                           |
| ---------------------------------- | ---------------------------- |
| `ls`                               | 列出全部名单，带状态分布和可节省的 token      |
| `cost [--top N] [--all]`           | 按开销排序，`--all` 带上内置与插件        |
| `show <名单>`                        | 看成员、状态、最后是谁改的                |
| `new <名单> [成员...]`                 | 新建名单                         |
| `pick <名单> [--append] [--numbers]` | 终端里交互式勾选，`--numbers` 是编号模式   |
| `add` / `rm <名单> <成员...>`          | 加人、踢人                        |
| `del <名单>`                         | 删名单，已经写进去的技能状态不动             |
| `on` / `off <名单>`                  | 恢复、休眠，`off` 加 `--hard` 是彻底关闭 |
| `status`                           | 看哪些技能被改过、来源是哪                |
| `log`                              | 最近 20 条操作                    |
| `restore`                          | 从最近一次备份恢复配置                  |

通用参数三个。`--dry-run` 只显示不写，`on` 和 `off` 支持。`--force` 在应用开着的时候强制写，也用来操作内置技能。`--config-dir X` 指定配置目录，必须写在子命令前面。

### 卡住了

**提示找不到 Python。** 脚本会先试 `python` 再试 `py -3`，两个都不行说明没进 PATH。重装的时候记得勾上 Add Python to PATH。

**8899 被占了。** 它会自己往后找，最多试 12 个端口，实际地址看窗口里打出来的。

**点关闭的时候提示应用正在运行。** 按第二步退干净，托盘图标也要退出。

**关了但没感觉变化。** 先想想重启了没有。重启过还没变，去操作记录里看这个技能是不是被另一份名单的操作盖掉了。一个技能同时在两份名单里的时候，后动的那次说了算。

## 四、如果你想改它

都是当时为什么这么选，留着给自己以后看。

### 只有一条写入口

```
浏览器 ui.html  --HTTP-->  skillui.py  --调用-->  skillset.py  --写-->  settings.json
                                                      ^
                                    终端 skillset.py --+
```

`skillui.py` 里没有任何写盘代码。每个接口把参数整理好，转手交给 `skillset.apply_to_settings()`，再把那个函数的打印和退出码截下来变成 HTTP 响应。界面和命令行走的是同一条路。这是故意的，两套实现迟早会跑偏。

`skillusage.py` 是另一条线，只读会话记录，不参与写入。

数据落在三个 JSON 里。`lists.json` 记住谁和谁一组，`ledger.json` 记住谁在什么时候改的，`settings.json` 才是当前生效的东西。前两个删掉不影响技能状态，它们只是记录。

| 要解决的问题     | 当时的选择                            | 代价                             |
| ---------- | -------------------------------- | ------------------------------ |
| 怎么知道应用开着   | `tasklist` 加强制进程名反查              | 只在 Windows 有用，换个应用名就漏检         |
| 怎么保证不写坏配置  | 备份、临时文件、原子替换，最后再逐字节比一遍           | 每次写入多两趟磁盘，配置很大的时候慢几十毫秒         |
| token 怎么估  | 拍了个系数，中文一字 1.5，其余 3.6 个字符一个      | 不是准数，只能横向比。想准就得引第三方分词库，零依赖就没了  |
| 终端怎么画      | 自己输出 ANSI 转义序列刷屏，方向键用 `msvcrt` 读 | 只在 Windows 有用，虚拟终端开不起来就退化成编号输入 |
| 悬浮窗给多少内容   | 只给前 1800 字符，而且不让鼠标进去操作           | 长文看不全。换来的是鼠标移开不会闪              |
| 用量怎么归到技能头上 | 只认会话记录里 `name` 等于 `Skill` 的那条    | 覆盖率很低，大约 2%                    |

最后一条展开说两句。技术上可以做得更准，只要看某一轮对话里助手有没有读过某个 `SKILL.md`，就能反推它用了哪个技能，覆盖率能接近百分之百。我没做。那是推出来的，会话记录里并没有这么一行。给一个来路说不清的数字，还不如老实标一句只统计显式调用。

## 五、它做不到的事

只在 Windows 上跑，`tasklist` 和 `msvcrt` 都是 Windows 专有的，Mac 和 Linux 上只能手工改配置。

写配置之前必须退出应用。配置在启动的时候读进内存，退出会把旧值刷回去，工具会拦住写入，`--force` 也改不了这个事实。

只能动用户级技能。`~/.workbuddy/skills/` 下面的才归它管，内置的和插件装进来的默认锁着。

按技能看用量基本不准。只有显式 `/技能名` 调用会留痕，实测覆盖 2% 左右。总积分和按会话的统计是准的。



### 怎么知道它还管用

这个工具坏起来是没声音的。WorkBuddy 哪天改了字段的意思或者技能缓存的结构，它照样写，照样不报错，就是不生效。所以别信上次还好用，隔一阵验一次，三十秒的事。

随便挑一个技能，点关闭，重启 WorkBuddy，然后看它还在不在技能列表里。不在就正常。还在的话先打开操作记录，看这一笔有没有被记下来。记了但没生效，是字段的意思变了。压根没记，那就是写入被拦了。
